# Инструкция администратора Соло-PR (CMS)

Краткая рабочая памятка для операторов сайта. Подробности редактирования текстов: [CMS_GUIDE.md](./CMS_GUIDE.md). Развёртывание VPS: [VPS.md](./VPS.md).

## Адреса входа

| Что | Путь |
| --- | --- |
| Вход | `/login` (устаревший `#/login` перенаправляется сюда) |
| Личный кабинет | `/account` |
| Панель управления / CMS | `/admin` |

На production откройте `https://<ваш-домен>/login`, затем `/admin`.  
Локально: `http://localhost:3000/login` → `/admin`.

Права проверяет сервер: обычный участник не видит контент редактора и не может сохранить CMS.

## Bootstrap-аккаунты администраторов

После развёртывания выполните на сервере (или локально с тем же `DATA_DIR`):

```bash
# Docker
docker compose exec community npm run seed:admins

# Без Docker (из корня репозитория)
npm run seed:admins
```

Скрипт `scripts/seed-admins.mjs` создаёт или обновляет **ровно три** администратора. Пароли хранятся в SQLite как **scrypt** (`salt:hex`), как у `scripts/admin.mjs` и API `/api/portal/login`. Пустых паролей нет.

### Учётные данные (plaintext bootstrap)

| Роль (организационная) | Email (логин) | Username | Пароль |
| --- | --- | --- | --- |
| Редактор CMS | `cms@vodopetov.ru` | `cms-admin` | `udozMo5OHM5fTzRXNvfxyUsP` |
| Операции сайта | `ops@vodopetov.ru` | `ops-admin` | `077vGrj60lMs0TYr1pEqcnte` |
| Сообщество | `community@vodopetov.ru` | `community-admin` | `pg2KZxKPEf0TydL1u1ZkiHku` |

Вход: укажите **email или username** и пароль на `/login`.

### Что может каждый аккаунт

В приложении одна техническая роль `admin`. Все три bootstrap-аккаунта имеют **одинаковые полные права**:

- редактирование и публикация всех текстов CMS;
- загрузка фото для карточек (курсы, видео);
- участники: клубный доступ, покупки курсов, документы;
- обращения / лиды;
- интеграции (voronka / lms_end / OIDC toggles, ping, flush outbox).

Разделение «Редактор / Операции / Сообщество» — для людей и ответственности, не для ACL в коде.

**Рекомендация:** после первого входа смените пароль в `/account` (блок смены пароля). Смена пароля завершает другие сеансы. Это bootstrap-учётки: ротация обязательна перед передачей продакшену внешним людям. Дополнительный сброс с сервера:

```bash
docker compose exec community npm run admin -- reset-password
# или ADMIN_EMAIL=… ADMIN_PASSWORD=… npm run admin -- reset-password
```

## Как войти в CMS

1. Откройте `/login`.
2. Введите email или username и пароль одной из таблиц выше.
3. Откройте `/admin`.
4. Если видите «Этот раздел доступен только администратору» — роль не admin: снова выполните `npm run seed:admins` или `npm run admin`.

## Редактирование текстов

Вкладки CMS:

| Вкладка | Назначение |
| --- | --- |
| Главная страница | Hero, вступления, блоки главной |
| Разделы сайта | Идея / Сообщество / Обучение / Бизнесу / Менторство |
| Все подписи и кнопки | UI-copy с поиском |
| Показ карточек | Порядок и лимит модулей на главной |
| SEO страниц | title / description / keywords |
| Программы / Видео / Библиотека / Мероприятия | Карточки контента |
| Название и контакты | Brand / реквизиты |
| Правовая информация | Политика, согласие, cookie, условия |
| Участники / Обращения / Интеграции | Операции, не «вёрстка» |

Порядок работы:

1. Внесите правки в форме.
2. Нажмите **«Опубликовать изменения»**.
3. Обновите публичную страницу.

Без публикации черновик остаётся только в редакторе. Одновременная работа нескольких админов не сливается — побеждает последняя отправка.

## Загрузка фото

### Фото карточек сайта (CMS)

В полях **«Изображение»** у программ и видео:

1. Нажмите **«Загрузить фото (JPG/PNG/WebP)»**.
2. Сервер сохранит WebP в `$DATA_DIR/media` и подставит URL вида `/api/portal/media/<id>.webp`.
3. Либо вручную укажите путь `/images/<файл>` (файлы из `public/images` при деплое) или HTTPS-адрес.
4. Опубликуйте изменения CMS.

Лимит загрузки: JPG/PNG/WebP примерно до 3 МБ; сервер уменьшает до 2400px по длинной стороне.

### Фото профиля

В `/account` участник (и админ) может загрузить аватар (до 2 МБ) — это не картинка сайта.

### Документы участнику

Во вкладке **Участники** → «Курсы и документы»:

- HTTPS-ссылка **или**
- загрузка файла на RU-том `$DATA_DIR/documents` (до 10 МБ).

Файл появляется в личном кабинете участника.

## Опросники (диагностики)

Отдельной вкладки «запуск опросника» в CMS нет: опросники — публичные страницы сайта.

| Опросник | URL | Кто проходит | Куда пишутся ответы |
| --- | --- | --- | --- |
| Диагностика специалиста | `/courses/diagnostika` | любой посетитель | только в браузере |
| Экспресс-диагностика для бизнеса | `/consulting/diagnostics` | любой посетитель | только в браузере |

Как «запустить» для аудитории:

1. Опубликуйте ссылку в текстах / кнопках CMS (вкладки «Все подписи и кнопки», разделы, меню через copy).
2. Или отправьте прямую ссылку `https://<домен>/courses/diagnostika` / `…/consulting/diagnostics`.

Тексты вопросов сейчас в коде (`src/lib/diagnostics.ts`, `ExpressDiagnostics` в `project.tsx`), не в JSON CMS. Чтобы изменить сами вопросы — нужен релиз кода. Подписи вокруг («Вопрос», кнопки) можно править во вкладке copy, если они заведены как SiteText.

Ответы **не** попадают в «Обращения» автоматически. Чтобы получить контакт после опросника, посетитель отправляет заявку (формы лида / заказа).

## Участники и доступы

- Клубный доступ — переключатель у участника (не у admin-учёток).
- Курс после оплаты — «Открыть доступ» (ручное подтверждение; оплаты на сайте нет).
- Обращения: заявки участников + гостевые лиды (email / Telegram / MAX).

## Смена пароля

1. Войдите → `/account`.
2. Укажите текущий и новый пароль (12–128 символов).
3. Другие сеансы завершаются; остаётесь в новом сеансе.

Если пароль забыт — сброс только с сервера (`npm run admin -- reset-password` или повторный `npm run seed:admins`, который перезапишет bootstrap-пароли из скрипта). Письменного self-service reset нет.

## Безопасность для оператора

- Не публикуйте bootstrap-пароли в чатах после ротации.
- Production ПДн — только RU VPS (`DATA_DIR` volume). Cloudflare Sites/D1 — не для реальных ПДн.
- Cookie сессии HttpOnly; на HTTPS держите `COOKIE_SECURE=true` и `SITE_ORIGIN`.
- Секреты интеграций только в env, не в CMS.
- Перед обновлением приложения: остановка → бэкап `$DATA_DIR` (sqlite + content.json + media + documents) → обновление.
