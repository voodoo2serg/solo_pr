# Управление сайтом Соло-PR

CMS встроена в сайт. Отдельную систему устанавливать не требуется. Администратор входит через `/login`, затем открывает `/admin`. Права проверяются сервером: обычный участник не получает доступ к редактору или сохранению контента.

## Первый вход на VPS

Нужен Node.js 24+. Создайте администратора командой `npm run admin` на сервере; скрипт запросит email и пароль. В Docker: `docker compose exec community npm run admin`. Секреты не публикуйте в репозитории. Если администратор уже есть, используйте его текущие данные.

## Что где редактировать

| Вкладка | Содержимое |
| --- | --- |
| Главная страница | Вводный заголовок, вступление, тексты о сообществе и материалах |
| Разделы сайта | Названия, вступления, содержательные блоки, цитаты разделов |
| Все подписи и кнопки | Остальные тексты интерфейса: меню, кнопки, объявления, хартия, форматы услуг, подписи. Есть поиск по исходному и текущему тексту |
| Программы | Карточки и страницы обучения, темы, изображения, статус и даты |
| Библиотека | Статьи, рубрики, доступ, полный текст |
| Видео | Название, адрес внешнего плеера, обложка и параметры публикации |
| Показ карточек | Порядок и общий лимит каждого модуля на главной |
| SEO страниц | Title, description, keywords по адресам страниц |
| Название и контакты | Контакты, реквизиты и сведения об операторе |
| Правовая информация | Тексты согласия, политики, cookie и условий |
| Участники / Обращения | Доступы к клубу, курсы и документы, входящие заявки |

Изменения сначала находятся в форме редактора. Нажмите **«Опубликовать изменения»**, чтобы сохранить их на сервере. Посетитель увидит новую редакцию при следующем открытии или обновлении страницы. При уходе с несохранёнными изменениями браузер предупреждает об этом. Одновременная редактура несколькими администраторами не объединяется: сохраняется последняя отправленная версия.

## Как редактировать любой текст, сохраняя вёрстку

Основное содержание меняйте в «Главная страница», «Разделы сайта», карточках и правовых документах. Для остальных подписей откройте «Все подписи и кнопки» и найдите видимый фрагмент. Подпись над полем — исходная формулировка, значение в поле — новая. Одинаковая исходная подпись изменяется во всех местах её использования. Содержимое выводится как текст: HTML и скрипты не исполняются. Меню, сетки, ссылки и состав разделов остаются частью шаблона.

Новые разделы и изменения структуры выполняются в коде. Технические идентификаторы записей остаются постоянными: они используются в адресах и доступах к программам. Поля ввода пользователя, адреса ссылок и технические сообщения внешних сервисов не являются редакционными текстами сайта.

## Статьи и видео: публикация и показ

1. Добавьте запись в нужной вкладке. Новая запись — **черновик**.
2. Заполните название и содержание; у видео описание в карточке не выводится, текстовый блок содержит только заголовок.
3. Включите **«Опубликовано»**. Без него запись отсутствует в публичных списках; черновик статьи недоступен и по прямому API-адресу.
4. **«Показывать на главной»** управляет только главной страницей. При выключении запись остаётся в библиотеке или каталоге.
5. Укажите дату публикации, если нужна сортировка по времени. Это дата для сортировки, а не отложенная публикация.
6. Опубликуйте изменения.

У статей отдельно остаётся доступ «Открыто всем / Только клуб». Клубная статья может показывать анонс; полный текст защищён серверной проверкой доступа. Видео в этой версии — открытые внешние публикации, без защиты платного видео. Секретные ссылки и закрытые уроки размещайте в учебной системе, а не в публичном видео-модуле.

### Порядок и лимит на главной

Во вкладке «Показ карточек» настройки независимы для статей, видео и курсов:

- **Сначала последние** — по дате публикации от новых к старым.
- **Сначала ранние** — от старых к новым.
- **Как расположены в CMS** — кнопки «Выше / Ниже» у записей задают ручной порядок.
- **Всего карточек в модуле** — `0` показывает все подходящие записи; `5` оставляет первые пять после сортировки.

В строке главной — **3 карточки на странице**. Лимит `5` означает две страницы: три карточки и две. Пагинация статьи и видео независима и стоит справа. При единственной странице она скрывается. На узких экранах карточки идут вертикально.

Записи без даты идут после датированных при порядке «Сначала последние»; между одинаковыми датами сохраняется порядок CMS. У старых записей дата не выдумывается — заполните её для точного порядка.

В библиотеке статьи и видео чередуются в общей выдаче, есть фильтры типа, доступа и поиск. На странице — до шести карточек. Лимит главной не обрезает библиотеку. Порядок каждого типа берётся из настройки соответствующего модуля. Каталог обучения также сохраняет все опубликованные программы.

## Внешние плееры

Видео загружается **по нажатию на обложку / «Смотреть»**, а не при открытии страницы. До нажатия iframe внешнего сервиса не создаётся. Обложка с внешнего URL при этом загружается как обычное изображение; для размещения обложек на своём сервере используйте путь `/images/...`.

### YouTube

Вставьте HTTPS-ссылку в поле адреса видео. Поддерживаются `youtube.com/watch?v=…`, `youtu.be/…`, `/shorts/…`, `/embed/…`. Пример формы ссылки: `https://www.youtube.com/watch?v=VIDEO_ID`. Сайт создаёт плеер на `www.youtube-nocookie.com`. ID должен содержать 11 допустимых символов.

### ВК-Видео

В официальном меню видео выберите экспорт / встраивание. Из полученного iframe скопируйте **только значение `src`**, например:

```
https://vk.com/video_ext.php?oid=-123456&id=789012&hash=abcdef
```

Поддерживаются `vk.com` и `vkvideo.ru` с путём `/video_ext.php`. Сохраните `oid`, `id` и `hash`, если он есть. Обычная ссылка на страницу ВК не заменяет экспортную ссылку плеера: для некоторых записей нужен `hash`. HTML `<iframe ...>` целиком вставлять не нужно. Другие домены и небезопасные адреса отклоняются сервером. Возможность воспроизведения зависит от разрешения автора, доступности видео и самого сервиса; это проверяйте на своей публикации.

## Карточка курса

Настраиваются название, описание, изображение, формат, темы, статус «Планируется / Идёт сейчас / Прошёл», публикация, показ на главной и дата публикации для сортировки.

**Дата начала курса** выбирается календарём и отображается на карточке и странице программы. Если дата не задана, используется «Дата для карточки». Если оба поля пустые, сайт пишет **«Дата набора уточняется»**. Дата публикации и дата начала — разные поля.

Изображение задаётся адресом: локальный `/images/имя-файла.webp` либо HTTPS-адрес. Локальные файлы добавляются в `public/images` при развёртывании; загрузчика файлов в CMS нет. Видеокарточке также можно назначить обложку.

## SEO

Откройте «SEO страниц». Для главной используется ключ `home`; основные разделы: `about`, `club`, `courses`, `consulting`, `materials`. У каждого есть заголовок страницы, описание и ключевые слова. Для отдельного материала или программы нажмите «Добавить SEO страницы» и укажите, например, `courses/expert-position` или `materials/solo-position` — без начального слеша.

На VPS страницы доступны по обычным адресам `/about`, `/courses`, `/materials` и т. д. Сервер формирует метаданные и публичное содержание при запросе; CMS-изменения не требуют пересборки. Для карточки без отдельного SEO используются её название и описание. Служебные страницы входа, кабинета, администратора, заказов и встреч получают `noindex`. Относительный canonical указывает обычный адрес страницы. Старые ссылки `/#/courses` перенаправляются в браузере на `/courses`.

Статическая сборка с Worker сохранена для совместимости: Worker подставляет метаданные из своей CMS, само содержимое там продолжает загружаться в браузере. Для серверной выдачи публичного содержания и основного развёртывания используйте VPS-вариант.

## Данные, резервная копия и обновление

На VPS редакционные данные находятся в `DATA_DIR/content.json` (по умолчанию `data/content.json`), пользователи, доступы и заявки — в SQLite в том же каталоге. Сохранение JSON атомарное. При обновлении кода старые записи получают недостающие настройки; существующие значения текста, SEO и порядка сохраняются.

Каталог данных должен быть постоянным томом Docker или постоянной директорией VPS. Не заменяйте его тестовыми данными и не коммитьте в Git. Перед обновлением сделайте резервную копию всего каталога при остановленном приложении, затем запустите его снова. Для восстановления нужны и JSON, и база пользователей. У альтернативного Worker-варианта отдельная D1-база; перенос данных между этими вариантами автоматически не выполняется.
